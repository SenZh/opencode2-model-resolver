# 需求分析 — limit 解析接入 models.dev

## 用户原始需求

用户报告：OpenCode 2 的 `cpa` provider 下三个模型 `gpt-5.6-luna`、`grok-4.7`、`hy4-preview` 的上下文长度全部被解析为 131072（13 万），而真实值分别为 1,050,000 / 500,000 / 1,024,000。用户要求定位根因并修复。

## 实现目标（可量化）

| # | 目标 | 可验证标准 |
|---|------|-----------|
| G1 | 找出并证实 131072 的根因 | 有运行证据链，能解释缓存中 22 条模型**全部**为规则库/兜底值 |
| G2 | 修复后 `gpt-5.6-luna` 解析为 1,050,000 | 单测断言 + 运行时缓存文件核对 |
| G3 | 修复后 `grok-4.7` 解析为 500,000 | 同上 |
| G4 | 修复后 `hy4-preview` 解析为 1,024,000 | 同上 |
| G5 | models.dev 不可用时不得用规则值污染已有缓存 | 单测：mock 空 Map，断言不覆写 |
| G6 | 现有 19 个测试全部保持通过 | `bun test` 全绿 |

## 范围界定

- **在范围内**：`src/index.ts` 扫描路径的 limit 解析；抽取公共权威 limit 解析函数；models.dev 失败的防护；缓存格式版本化。
- **不在范围内**：`lookupModelsDev` 匹配算法重写（属脆弱性优化，非本次根因）；生图模型 0 值过滤策略（需产品决策，转为遗留问题）。

## 需求与契约对应

见 `contract.md`。G1 对应根因确认，G2-G4 对应主路径，G5 对应边界/异常，G6 对应相邻影响。
